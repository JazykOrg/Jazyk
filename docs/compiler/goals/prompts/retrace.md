This goal repairs one node whose upstream died: a curated view lists a dead member (in members, excluded, or collapse), a derived fact lost a node from its from set, the requirement stating an instance's instantiation died, an attribute's provenance quote died with its section. The change line names the dead node, the reason, and the generation; load the target in full and find every place it still points at the dead id (marked deleted in the loaded item). Decide per reference: repair it (point it at the surviving node that states the same thing, found with search or named by the hints as the likely replacement, or at the redirect target of a merge), re-derive it (a derived fact's from set and reasoning rewritten over live upstream; an instance re-linked through the requirement that still states the example; an attribute re-anchored to the sentence that still states it), or drop it (update_view remove_members for a view, update_entity for an attribute, update_requirement for an edge on a derived requirement), and delete the target itself (delete_view, delete_entity, or delete_requirement, with a reason) only when nothing is left for it to describe or justify. For a flow view, keep the order true: read the surviving members as a flow before deciding, and when a removed step carried a failure-mode branch the branch goes with it and the justification says so; split the view with upsert_view only when the survivors fail to form one flow. For an entity, keep only the definition, parent, stereotype, attributes, and edges a surviving statement supports. Default views, relationships, and state machines recompute at commit and are never retraced by hand. Never re-create the dead node to make a reference valid, and never invent a replacement the documents do not state: a fact the documents still state comes back through reconcile-section under its natural key, not through this goal. When the loss leaves a real gap, file report_diagnostic naming the target and what it lost: missing-link when the documents rely on a step or a part they stopped stating, decision with a prompt when the repair is a human's choice (drop the flow, or restate the step); deleting a derived fact retracts its open ratification proposal with it. The skill for the node kind you load (flow-views, structural-views, abstraction, conformance, extraction) says how that kind is read. Fail the goal only when the node can be neither repaired nor deleted with the evidence in the graph. The gate: nothing on the target points at a dead or missing node; mark_goal_done is rejected naming each reference that remains.
