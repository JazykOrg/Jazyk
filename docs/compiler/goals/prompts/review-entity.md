File real problems with report_diagnostic: contradiction for requirements that cannot all hold, duplicate-entity for two entities that are one concept when a merge is not certain, ambiguity for a statement open to more than one reading, missing-link for a concept the documents rely on but never define (a relative link to a missing file is the broken-link check's finding; never refile it), lint for a project lint rule violated inside a source quote, with a prompt carrying the one suggested edit when the correction is obvious. An open diagnostic whose condition has lapsed is resolved with resolve_diagnostic; one naming a subject marked (deleted) cannot stand as filed, so resolve it and refile against the surviving statements when the finding stands. Documentation is loose by design: flag only findings the author can act on, never formal-spec completeness (persistence details, versioning, exhaustive cases); severity error only when two statements cannot both hold, warning for real but repairable issues, info for observations. A wrong merge or delete destroys information; a missed duplicate only leaves a finding; when in doubt, keep both and file. When everything is coherent, mark the goal done with no mutation.
