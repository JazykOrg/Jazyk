Change detection and identity

The compiler aligns the new section tree with its stored one and derives work from the change. It does not discard the graph and re-extract every document.

Names can change without changing identities. A merge redirects the old ID. A moved section can retain its facts when alignment recognizes the move. A changed quote may need review before its anchor is trusted again.

What changes after an edit

This is an illustration of the contracts, not a compiler run. Choose a kind of edit to follow the likely work.

The cancellation rule

Changing the cancellation day means reconciling the affected section and rejudging its requirements. Derived criteria may become stale. Bound tests and implementation evidence need review.

Prose edit → Reconcile → Review evidence

Journal and causal history

Each committed changeset records a generation in the journal. Opened goals carry causes; resolved goals carry justifications. This gives you a path from an edit to its downstream work.

Example · replace angle-bracket placeholders 
jazyk status
jazyk explain <goal-or-target> --set Main
jazyk ripple <target-or-generation-or-doc> --set Main
jazyk ripple <target-or-generation-or-doc> --set Main --back

explain tells you why work exists. ripple follows the causal chain; --back walks toward the change that started it. You do not have to reconstruct the build from chat recollections.

Preview and session limits

Terminal 
jazyk preview --set Main

Preview assembles the next session prompt. Read which goals, changes, and context the agent will receive. It is particularly useful when a small edit seems to open unexpectedly broad work.

To bound a diagnostic run, use jazyk compile --set Main --sessions 1. An unfinished run reports incomplete honestly; later work continues from committed state.

Change review checklist

  • Did the prose change the intended obligation?
  • Are the graph facts and diagrams consistent with it?
  • Do the examples still express the boundary?
  • Which tests and source files became stale?
  • Did a proposal introduce a new product choice?

A no-op rebuild derives no new goals and makes no LLM calls. If a supposedly unchanged project keeps opening work, inspect its change records, failed work, and unstable judgments rather than assuming more retries will settle it.
