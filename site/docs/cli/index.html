USAGE GUIDE / CLI

Work from the terminal.

Set up a local project, compile your documents, and follow the result through generation and verification.

Before you start

You need Git, a current Rust toolchain, and an AI agent or model for compilation. The local compiler uses your own AI access. A Cloud account is not required.

1. Install the local compiler

Build the current compiler from the public source repository. Run these commands in the directory where you keep projects.

Terminal
git clone https://github.com/JazykOrg/Jazyk.git
cd Jazyk/bootstrap
cargo build --release
export PATH="$PWD/target/release:$PATH"
jazyk --help

The export makes jazyk available in this terminal. For later sessions, add the absolute Jazyk/bootstrap/target/release path to your shell configuration. GUI editors also need that path, or an explicit binary setting.

2. Create a project and select documents

In a new folder, initialize the project. Choose your installed coding agent when prompted, or keep the embedded agent and configure its model in the next step.

Terminal
mkdir my-project
cd my-project
jazyk init
mkdir -p docs

Create docs/main.md and write a small first document. Then select it as a named document set.

Terminal
jazyk sets add Main --docs 'docs/**/*.md' --roots docs/main.md
jazyk sets list

jazyk init creates .jazyk/jazyk.toml with no document sets. sets add records your selection. Quote globs so your shell passes the pattern to Jazyk.

Already have documents?

Run jazyk init in the existing project folder, then add a set with the paths you use. Documents do not have to live in docs/.

3. Choose the AI that does the work

There are two paths. Use an installed coding agent through its ACP adapter, or let the embedded agent call an OpenAI-compatible model endpoint.

Use your coding agent

jazyk init offers codex, claude, and opencode. The agent must be installed and authenticated. Codex and Claude use ACP adapters launched through npx, so they also need Node.js and network access for the adapter.

To choose an agent for an existing project, run:

Terminal
jazyk init --agent claude

Use the embedded agent

Put your endpoint and model in ~/.jazyk/config.toml. This example uses a local OpenAI-compatible server. Replace the model name with one your endpoint actually serves.

Example · ~/.jazyk/config.toml
[llm]
base_url = "http://localhost:11434/v1"
model = "your-model-id"
api_key_env = "JAZYK_API_KEY"

For a hosted endpoint, change base_url and set JAZYK_API_KEY in your environment. Keep credentials out of tracked files. CLI flags and environment variables override set, project, and global settings.

Check a new agent or model before trusting it with your project:

Terminal
jazyk benchmark

The benchmark checks session capability. Small local models can fail it even when the server responds. Choose a model that passes before interpreting a poor result as a problem with your documents.

4. Compile, inspect, and decide

Terminal
jazyk compile --set Main
jazyk status
jazyk preview --set Main

The compile prints live work and a final verdict. preview shows the next session prompt so you can inspect what would be sent to the agent.

ResultWhat to do
ConvergedRead the graph and diagrams. Check any blocked or optional counts beside the verdict.
IncompleteRead the remaining or failed work in jazyk status. Fix setup or docs, answer questions, then compile again.
Needs your answerUse jazyk answer with the diagnostic ID to list its options. Review the question before replying.
Example · replace the diagnostic ID
jazyk answer diag:your-id --set Main
jazyk answer diag:your-id --set Main --text 'Your decision'
jazyk compile --set Main

Answers can trigger agent work and proposed document edits. Read the affected prose and recompile after a decision. jazyk explain shows why a goal exists; jazyk ripple traces a change through the journal.

5. Generate and verify a deliverable

When you are ready to produce files, add their allowed paths to the set. The following example permits files under src/ and tests/. Include other required files explicitly, such as a package manifest.

Example · a software project
jazyk sets update Main --source 'src/**' --source 'tests/**' --source package.json
jazyk gen --set Main
jazyk test --set Main

gen binds requirements and generates into the selected source paths. test verifies the recorded criteria. Generation and verification can call your agent. Read the evidence; a generated test is not a passing test.

A deck or another artifact uses its own source paths and verification criteria. The file selection defines where generation may write.

Commands for everyday work

When you want to…Run
Recompile after saved editsjazyk watch --set Main
Compile and check error diagnosticsjazyk check --set Main
Find an entityjazyk query "Sort" --set Main
Inspect why work is openjazyk explain <goal-or-target> --set Main
Read generated graph documentationjazyk docsgen --set Main
Export an offline graph viewerjazyk viewer --set Main
Read a command’s optionsjazyk <command> --help

Bare jazyk compile runs all dirty sets, one at a time. Use --set with the set name or ID for a specific graph operation. check runs compilation too; it can use AI.

Open the same project in a browser

Terminal
jazyk gui

This starts the local API and opens jazyk.dev connected to your computer. Keep the process running. The project’s files and compiler stay local; no Cloud sign-in is needed.

You can also connect your IDE and continue working in the same folder.

Know where things are saved

LocationContains
docs/, or your chosen pathsYour authored documents.
.jazyk/jazyk.tomlNamed document sets and project settings. Track this in Git.
.jazyk/.gitignoreIgnore rules for generated state. Track this in Git too.
.jazyk/<set-id>/The graph, diagrams, diagnostics, journal, and transcripts. Keep generated state ignored.
Selected source pathsThe files the set describes and may generate.
~/.jazyk/config.tomlMachine-level agent or model defaults.
