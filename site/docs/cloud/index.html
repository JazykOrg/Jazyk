USAGE GUIDE / CLOUD

Create in the browser.

Keep a project online, compile with included AI, and deliver to GitHub when the result is ready.

Files and AI are hosted

Cloud projects are saved online and compiled with included AI. Local folders and demos in the same editor remain available without an account. Signing in does not upload your local project.

1. Open a Cloud project

  1. Sign in at jazyk.dev

    Open the editor, choose Cloud, and sign in with GitHub. Your first eligible sign-in starts a 14-day Cloud trial. The app shows your trial dates and available usage.

  2. Create or import

    Choose New project for a fresh project, or Import from GitHub for an existing repository. Repository access is a separate grant from signing in. Choose the repository and branch you intend to use.

  3. Choose your document set

    In Document sets, select the documents about your subject and, when needed, the source files they describe. Imported files are not all assumed to be documents. Start with one focused set.

2. Write, build, and inspect

In Docs, write or edit the prose. State the behavior you want and include concrete outcomes. For a non-software project, describe the artifact and its constraints.

Select the intended set in the Build control, then start the build. Build runs compile, generation, and review in sequence when those steps have work. Select source paths only when you want the set to describe or generate those files.

In the editorLook for
DocsYour authored text and the sentences behind the graph.
ModelEntities, requirements, criteria, and diagrams. Check that the model matches your intent.
ProductThe selected source files, generated results, and recorded verification evidence.
InboxQuestions, proposals, and problems that need attention.
HistoryThe committed changes that explain how the project got here.

The build thread shows progress and any pause or failure. Read the result, then use the model and evidence to decide what needs another edit.

3. Resolve the decisions

Use Inbox to answer questions and review proposed additions to the docs. An ambiguity needs your intent. A proposal needs your judgment about whether that fact should become part of the prose.

You can also edit the documents to clarify a requirement. Save, then run Build again. Cloud builds run on request; saving a document alone does not start a hosted build.

Read the evidence as well as the result

A build may produce files before every criterion has current verification evidence. In Product, check for failing, missing, or stale evidence. A passing GitHub workflow alone does not prove that all criteria were tested.

4. Deliver when you are ready

Building a Cloud project saves its results in that project. Publishing them to GitHub is a separate action.

  1. Choose a destination

    Open the project’s Settings to manage GitHub access and deliveries. Select an accessible repository and branch, or create a delivery repository when that permission is available.

  2. Review the delivery

    A Git delivery publishes selected files. A script delivery runs its configured command in GitHub Actions. Check the files, destination, and command before executing it.

  3. Confirm and follow the run

    Use Deliver. Review the repository and branch in the confirmation. Run history shows the attempt, its commit, status, logs, and any criterion evidence.

Signing in and linking a repository do not publish files. If a delivery’s outcome is unknown after an interruption, inspect its existing run before starting another.

Plans and included AI

Open Plan & usage from Home or your account menu. It shows the current trial or plan, remaining usage, resource limits, and when usage becomes available again.

Available paid plans and current prices are listed there. When paid plans are unavailable, the app says so. Use the app’s current offer to decide how to continue after the trial.

If a build pauses at a usage limit, committed changes stay saved. Read the pause reason and check Plan & usage before resuming. A service availability error needs service recovery rather than a plan change.

Back up your work

On Home, a Cloud project offers Download backup. Keep a backup before major changes. Import project backup restores a backup as a project through the app’s import flow.

A GitHub delivery preserves the files it publishes. It is a different action from backing up the Cloud project. Review each destination before you transfer work.

When work is interrupted

A build stopped or paused

Read its reason in the build thread. Earlier committed changes remain saved. Fix the reported issue or wait for capacity or usage to recover, then start Build again.

Your sign-in expired while editing

Keep the tab open and sign in again with the same account. The editor retains unsaved drafts for that account and project when session storage is available. Confirm the draft is saved before closing the tab.

You want to keep working locally

Open a local folder in the editor, or follow the CLI guide for a local compiler. Local projects use your own agent or model and do not require a Cloud subscription. Switching projects does not transfer files between them.
