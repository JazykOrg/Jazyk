Docs / Existing projects

WORK WITH CHANGE

Start with what already works.

Document and bind a focused part of an existing project before expanding or generating.

On this page
Adopt one part first Draft docs from existing code Review description against intent Expand when the first slice is useful

Adopt one part first

An existing project does not need to be regenerated. Pick one behavior or subsystem, add documents for it, and select the existing source paths it describes.

Compile the documents and inspect the graph before asking for generation. Binding can connect the requirements to current files and tests. Start with evidence you already trust.

Example · a focused set 
jazyk sets add Orders --docs 'docs/orders/**/*.md' --source 'src/orders/**' --source 'tests/orders/**'

Draft docs from existing code

Decompilation reads source and produces prose drafts. Tests are strong evidence because they already assert observable behavior. Implementation alone can show what happens without explaining whether it is intended.

Example · selected source scope 
jazyk decompile src/orders --set Orders

Drafts distinguish observed behavior backed by tests from behavior inferred from code. They land in the docs selection and follow the normal compile path. Decompilation does not place code-derived requirements straight into the graph.

Review description against intent

A bug faithfully described is still a bug. Review each draft for whether it states what the product should do, not merely what it happened to do.

Draft documents remain provisional until human editing changes their recorded hash. Revise their statements, clarify assumptions, and compile. The docs become the source of the graph’s obligations.

Do not broaden generation paths until you have checked the graph, bindings, and existing test evidence. A source selection grants write scope; it does not certify that generated replacements are needed.

Expand when the first slice is useful

The unclaimed report identifies source files with no recorded binding. Use it as a map of territory to investigate, not as proof that every unclaimed file is wrong.

Add the next subsystem, or a separate set for another subject. Keep shared docs deliberate. Continue until the model and evidence cover the area you care about.
