From prose to something you can inspect

Describe what you want to create: a program, slide deck, organization, or story. Jazyk keeps a semantic graph behind the documents, with requirements, criteria, entities, and diagrams.

Write→Compile→Review→Generate→Verify

  1. Write the intent

    Name the things involved, state what they do, and include concrete examples. Use ordinary prose. Link related documents so a reader can follow the subject.

  2. Compile the documents

    Jazyk reconciles the graph with your prose. Read the requirements and diagrams to check what it understood. Compilation itself does not mean a finished deliverable.

  3. Make the decisions

    Resolve contradictions and answer questions. Review proposed additions to the prose. Your decisions become part of the project, then another compile brings it up to date.

  4. Generate and verify

    Select the source files the document set describes before generating. Jazyk can produce code or another deliverable and verify it against the criteria. Inspect the result and its evidence.

Write a first document

Start with one small behavior and an example of its outcome. This excerpt is from the sort utility on the home page.

Document excerpt
# Main.ts

This is a simple sorting algorithm CLI utility similar to the `sort` CLI command.

## CLI args

When invoked, `sort` allows the following CLI args:
- `-r` reverses sorting order to descending

For a deck, name its audience and what each slide must communicate. For a story, name its characters and what happens. Concrete constraints give you something to review when Jazyk compiles.

Keep related documents together

A document set selects the documents about one subject and the source files they describe. Each set has its own graph, diagnostics, diagrams, and build state. Start with one set. Add more when your project has distinct subjects.

In the editor, use Document sets to choose files. In the terminal, use jazyk sets add. Choosing files does not start a build.

Know what to look for

  • Requirements: do they say what you intended?
  • Criteria: is the expected outcome observable and concrete?
  • Diagrams: do the entities and flows fit your subject?
  • Questions and proposals: what needs your judgment?
  • Verification: which criteria passed, failed, or need fresh evidence?
A clean compile is one checkpoint

A converged graph has no remaining mandatory work and passes the compiler checks. Human-blocked work can still be listed beside that verdict. It is not proof that every generated result has been verified.
