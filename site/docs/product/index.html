GENERATION AND TESTS

Generation

Bind requirements to files and tests, then generate the required artifact.

On this page
Generation input Source write scope Bindings and existing implementations Artifact medium and toolchain Running generation and verification

Generation input

Compilation makes a semantic graph. Generation reads that graph as its specification. Requirements say what the product owes; criteria say how to recognize it.

Compile → Bind → Generate → Verify
Stage Result
Compile Facts and judgments reconciled against the docs.
Bind Criteria tied to tests, and requirements tied to implementation files or missing implementations.
Generate Files or build sources that implement the requirements.
Verify Recorded outcomes and evidence for the criteria.

Source write scope

The document set’s source selection defines its allowed product paths. Start narrow and include required support files explicitly.

Example · a software project 
jazyk sets update Main --source 'src/**' --source 'tests/**' --source package.json

A slide project could select slides/** and its build script instead. Source files can already exist. Choosing them does not prove their coverage and does not by itself release generation.

Docs are excluded from generation write scopes. Keep generated state separate from the authored prose and selected product files.

Bindings and existing implementations

Binding looks for the implementation and establishes tests against the criteria. A requirement can already be satisfied by existing files. There is no need to replace working code simply because it was not generated by Jazyk.

The ledger records implementing files, test artifacts, run commands, and evidence. Generation handles missing or changed obligations. Missing information becomes a decision to review rather than an invisible assumption.

Artifact medium and toolchain

If the documents ask for a manuscript, the text files may be the artifact. If they ask for a deck, PDF, rendered site, or binary, sources must build the requested artifact and tests must inspect that result.

The workflow records the medium and toolchain once and carries that decision into later sessions. State a required format or language in the docs; the project config selects paths and execution settings, not the product’s intent.

Content must be present

A requirement for a title, definition, color, or behavior is satisfied only by the actual content or behavior. Placeholders and descriptions of future work do not meet it.

Running generation and verification

Terminal 
jazyk gen --set Main
jazyk test --set Main

These commands can call your agent and write within the selected source paths. In the GUI, Build groups compile, generation, and review when work exists. In Cloud, delivery to GitHub is a separate confirmed action.

Inspect the actual result, not just a success message. Follow its requirements to the current evidence. A complete graph and a verified artifact are different checkpoints.
