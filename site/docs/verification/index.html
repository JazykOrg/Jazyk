LEARN THE COMPILER

Know what has been proved.

Read criteria, test outcomes, and freshness together before deciding that a product is ready.

Start with an observable criterion

A requirement is the obligation. A criterion is one condition and its observable outcome. A test is the artifact that evaluates that criterion.

ILLUSTRATION / ORDERLY

Requirement
Orderly cancels an unpaid Order at the start of day 22.
Criterion
An Order placed on day 0 and unpaid at the start of day 22 is cancelled.
Evidence
A recorded evaluation of that condition against the current implementation.

One rule may need several criteria: a positive case, a failure path, and boundary values. A test saying only “cancellation works” has lost the condition you need to evaluate.

Programmatic and model-based tests

Programmatic tests execute a recorded command and evaluate its results. They fit deterministic behavior, structure, values, and interfaces that a runner can observe.

Model-based tests judge an artifact against criteria that require interpretation. They can assess content and other qualitative obligations. They still need the actual artifact and recorded evidence. A model’s judgment is evidence of its evaluation, not certainty about every possible use.

Use a reproducible check when one can express the criterion. Keep the judge’s reasons visible when interpretation is necessary.

Read status with its freshness

State or finding Meaning Next step
Verified The recorded evaluation passed for its inputs and artifact state. Inspect the evidence and coverage.
Failing An implementation exists but does not meet a criterion. Inspect the product, test, and docs; fix the right one.
Unimplemented The requirement has no implementing files. Generate or supply the missing implementation.
Stale code or test A recorded input changed after evaluation. Rerun verification.
Missing evidence No qualifying result is recorded. Bind a test or evaluate the criterion.

Changing source or tests invalidates evidence. An old pass should not be read as a result for a new artifact. CI evidence is also tied to its project revision and criterion mapping; a green workflow without that mapping is not a pass for every requirement.

Three different questions about coverage

  • Document coverage: has a section been reconciled or judged non-normative?
  • Implementation coverage: which requirements are tied to product files?
  • Verification coverage: which criteria have current evidence?

These are different questions. Compiling every section does not establish that every obligation is implemented. A generated test file does not establish that it ran.

Convergence is a compiler verdict

A converged build has no open or failed mandatory goals and passes its checks. Blocked and optional counts still travel with the verdict. Read the evidence before treating the product as ready.

Audit bindings after artifact edits

Terminal 
jazyk test --set Main --audit
jazyk test --set Main

--audit rebuilds the ledger from artifact markers without running tests. Use it to repair bindings after files or test artifacts have changed. An audit does not turn an edited artifact into a verified result. Run verification afterward to obtain fresh evidence. Independently review whether the tests observe the required outcome, medium, and values.
